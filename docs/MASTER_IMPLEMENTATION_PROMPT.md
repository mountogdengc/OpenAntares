Retain C#/Godot separation, deterministic integer simulation/PCG32, shared commands, stable IDs, content validation, theme conventions and save compatibility. Do not redesign or implement AI/diplomacy/combat/networking from architectural hooks. Record materially unresolved product, UX, licensing, architecture or compatibility choices instead of silently deciding them.
3. **Prepare execution.** Map tasks to REQ/AC IDs; order state/content/command/persistence/simulation/UI changes by dependencies. Inspect/reuse appropriate branch/worktree arrangements without disturbing the owner's dirty checkout. Plan cohesive testable units and a usable integrated milestone, not disconnected stubs.
4. **Implement and verify each unit.** Reproduce a defect before fixing it. Add meaningful boundary, invalid-input, atomicity, determinism and continuation tests when contracts change. Build and execute tests; diagnose failures and rerun relevant checks after repair. For Godot-only behavior, execute reproducible graphical interaction checks and retain evidence. Do not infer behavior from code generation or compilation.
5. **Validate the milestone.** Execute every relevant criterion, including actual startup/content/save workflows, negative cases and manual checks. Record exact environment, commands, outcomes and artifacts. Mark missing manual/target-platform evidence unverified. Preserve player saves and use unique QA names. A successful local `--no-restore` run does not prove clean installation, dependency security or exported delivery.
6. **Review integration.** Review the intended diff and branch/worktree inventory, reconcile documentation and run checks on the intended combined result. Integrate/push/release only within owner authorization. Do not discard unrelated work or automatically delete branches/worktrees. Record the final verified SHA and remaining local changes; do not label a dirty snapshot a clean release.
7. **Handoff honestly.** Update requirement statuses, evidence, decisions and `PROJECT_STATUS.md`. Report verified, incomplete, blocked and deferred work, material limits, actual integration state and next concrete task. Continue within the authorized milestone until complete or a real external decision/resource blocks progress; do not expand the scope to hide a blocker.
